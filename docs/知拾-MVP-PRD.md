# 知拾：文献阅读与笔记工作台

**产品需求文档 · MVP v0.2 · 2026-09-19**
面向用户：以中文法学研究、阅读与写作为主的个人研究者。
交付物：本 PRD + `demo/` 中可独立运行的前端交互演示。本文区分拟开发能力和演示已实现能力，不以演示数据证明真实解析、问答或引注准确率。

## 1. 产品目标与边界

每天接触的资料分散在 PDF、网页、截图、Word、Excel 和零散文字中。只保存文件难以再次找到内容，只生成摘要又容易失去原文依据。知拾的目标是：**先可靠留存，再低负担整理，最后在写作中准确调用有出处的材料。**

MVP 完成一个闭环：收录资料 → 找到并阅读原文 → 留下可追溯的笔记 → 按问题找出证据 → 导出写作素材与引注草稿。

默认假设：Windows 单人使用、本地优先、中文为主兼容英文；采用“研究主题目录 + 文献类型 + 自定义标签”。按用户指定的 10 个一级主题预置分类（见 4.3.1），以已解析的内容摘要为主要分类依据，按最相近原则自动归类；一篇文献可归属多个高度相关主题，允许人工修改。一级分类体系已确认，实际分类偏好仍需通过用户确认的文献样本校准。

### 成功标准（验收目标，非当前实测结果）

| 场景 | MVP 验收目标 |
| --- | --- |
| 临时捕捉 | 入口到提交不超过 3 步；资料落盘后立即可见，不等待语义分析 |
| 离线使用 | 无 API Key 时仍可保存、检索本地可提取文字、手动分类、阅读及记笔记 |
| 不丢原件 | 解析失败仍保留原件与任务状态；同一文件重复导入可识别；导出后可恢复 |
| 可追溯 | 进入回答的每条证据必须携带 source_id 和可验证定位；无位置的内容不包装成精确引用 |
| 全文覆盖 | 明示“已解析页 / 总页数、跳过区块”；仅部分解析时不标成“全文摘要” |
| 可靠问答 | 20 个自建研究问题人工验收：回答中无无源论断；至少 5 个无答案问题全部正确提示依据不足 |
| 阅读质量 | 12 份固定验收样本（六类格式各两份）全部可回看原件；修复断行不改变原始文字层 |

## 2. 核心用户故事

1. **先收住再整理**：看到一段文字或一个链接时，立即收录；会议截图先归入待整理，晚些时候再处理来源与识别。
2. **读完能再找到**：打开 PDF 看原页，切到整理阅读视图；保留表格、配图和脚注位置，把个人判断记在旁边。
3. **让分类越来越省事**：系统依据内容摘要，说明最相近的主题及归类理由；跨主题文献可同时出现在多个目录。我可以增删主题归属、调整主主题，并选择将已确认结果用于后续分类参考。
4. **写作时调用证据**：限定某篇论文或某个研究目录，问“哪些文献支持这一观点，有没有不同意见”，查看原文、位置与出处后采用。

## 4. 信息架构与关键流程

主导航：**文献库 / 我的笔记 / 证据问答 / 解析与偏好**。收录为常驻主操作；侧栏按 4.3.1 的顺序展示 10 个一级主题。“全部文献”“待整理”为系统视图，不计入十类。“待整理”表示处理状态，可与主题归属并存。

### 4.1 收录与任务状态

1. 上传文件、粘贴链接或文字；可填标题、来源及研究目录。
2. 先存档：计算文件哈希；同哈希时提示已有条目，可附加笔记，不重复写原件。网页按规范化 URL 提示重复，不把更新页面盲目合并；每次快照有采集时间。
3. 本地解析并显示进度：已存档 → 本地解析中 → 待 OCR / 待补来源 / 待核对 / 已整理。独立记录存档、解析、索引、语义分析各阶段状态，重试只处理失败阶段。
4. 提取正文、结构块和来源候选，形成带覆盖范围的内容摘要后自动分类；显示主题及依据。摘要缺失或置信不足时进入待整理，保留可解释的候选，不将解析失败误归为“其它”，不臆造出版信息。
5. 如需调用云端，按用户在设置中的授权执行；首次或超出授权范围时展示将发送的内容及估算。取消调用不影响存档和阅读。

界面必须区分“存档成功”“解析成功”“语义分析成功”，不以一个绿色成功标志替代三个状态。超时、加密 PDF、损坏文件、乱码、网页抓取失败均可重试或手动补正文。

### 4.2 阅读与记录

左侧目录和列表，中间阅读，右侧摘要 / 观点 / 个人笔记 / 来源信息。原件与整理阅读视图随时切换。高亮或观点点击后定位到原页或具体区块。

| 格式 | 本地处理优先 | 阅读与定位 | 失败回退 |
| --- | --- | --- | --- |
| 文本 PDF | 提取文本块、坐标、页数与嵌入图片 | 原 PDF + 重排；文件页索引与印刷页码分别保存 | 原件保留；疑似扫描页进入 OCR 队列 |
| 扫描 PDF / 图片 | 可选本地 OCR；无引擎时待识别 | 原图与识别文字并排；页/图编号及区域框 | 经授权调用视觉/OCR API；低置信文字标注 |
| DOCX | 段落、标题级别、表格、图片、脚注 | 结构化 HTML；用标题路径和段落编号定位 | 图表不可结构化时保留原图；不虚构 Word 页码 |
| XLSX | 工作表、单元格、合并区域、值与公式分别记录 | 表格视图、工作表切换、单元格范围；保留可提取图片 | 不执行宏；公式无缓存值时显示公式及“未计算” |
| 网页 | 提取正文、标题、作者、发布日期、URL、访问时间；保存快照 | 清洁阅读 + 快照；段落锚点 | 无法访问时仅存链接，提示粘贴正文 |
| 文字 | 编码、空白规范化、保守断行修复 | 保留 raw 与 clean 两个版本；段落定位 | 用户可恢复原始文本，未附来源时明确“待补全” |

排版原则：只改变显示层；疑似段内换行可合并，但不破坏标题、列表、诗句、代码和表格。中英文断词恢复须有上下文条件。页眉页脚移除必须可追溯和撤销。无法确定的乱码保留并标记，不让模型猜字后覆盖原文。

表格和图像必须作为独立区块：原始内容、图表编号、所在页、上下文说明、识别状态分别保存。表格行列不能简单拉平成一段文字。跨页表格合并与复杂图表理解列入 P1，MVP 可先回看原件。

### 4.3 全文提炼与分类

**正则擅长识别格式，不能代替全文语义理解。** 文档结构用格式解析器；DOI、日期、页码候选等用规则；核心论点和条件关系在规则不足时交给已配置模型。

无 Key：按标题/章节分块，生成高频关键词及抽取式候选句，并明确“抽取式阅读线索，不是语义综述”。允许人工编写摘要。有 Key：按章节分块提炼问题、中心命题、论据、限制与反对意见；汇总时保留每条观点的 block_id。不能只把摘要页的内容当成全文结论。

模型输出为候选：必须验证 evidence_id 存在、引文属于该原文区块、定位可解析；事实性引语须精确匹配原始文字。概括可以不同于原句，但不得冒充直接引用。遇到全篇中断，输出覆盖范围和未处理章节。

关键词 5–10 个，允许编辑。一级主题与自由标签分开管理；主题允许多选。可标记一个最相近的主主题用于默认排序，但文献在所有已选主题中均可见。

#### 4.3.2 自动分类决策

1. **摘要优先**：主要依据对已解析内容形成的摘要，包括研究对象、核心问题、观点和应用场景；标题、关键词和必要原文片段仅作辅助。不能因标题或正文偶然出现一个术语，就忽略摘要所表达的中心内容。
2. **最相近原则**：比较摘要与九个具体主题的范围，选择实质关联最强的一类作为主主题。可参考摘要与用户已确认分类文献的相似性；相似样本数量不能替代内容判断，重复文献不能通过数量优势影响分类。
3. **多主题归属**：摘要对多个主题均有充分、直接的内容支持时，可同时归入这些主题；与不同主题下多篇已确认文献特别相近，也可作为多主题归属的参考。每一个附加主题都应给出摘要依据，不能因提到某个词或检索命中很多文章而泛化加类。不设“只能归入一类”的限制。
4. **不确定与其它分开**：摘要完整但与前九类无实质关联时归入“其它”；摘要缺失、解析不完整或候选难以区分时标为待整理/待核对。自动分类默认不将“其它”与具体主题同时选中；人工调整时提示用户检查冲突。
5. **非模型优先、模型补充**：先对可用摘要进行显式规则和本地相似度判断；规则足够明确时直接归类。语义关系或跨主题边界不明确时，按用户配置的 API 与授权策略调用模型。无 Key、调用失败或额度不足时保留候选及原因，允许手动选择，不虚构分类成功。
6. **解释与校准**：保存分类依据的摘要版本、方法、规则/模型版本、候选主题、相似度或置信信息及简短理由。相似度不直接标成准确概率；自动接受与附加主题的阈值通过验收样本校准，不预设未经验证的准确率。摘要更新后，对未确认分类可重新计算；已被用户修改或确认的归属只产生新建议，不自动覆盖。

#### 4.3.3 人工调整与目录行为

- 文献详情及列表提供“调整分类”：十类可多选，可增删归属并指定主主题；保存后立即更新所有目录中的显示。
- 一篇文献只保存一份原件和一个 source_id，多主题采用关联关系，不复制文件、正文或笔记。修改笔记在所有主题入口一致可见。
- “全部文献”及跨目录检索按 source_id 去重；每个主题计入其关联文献，因此主题计数之和可能大于文献总数。多主题筛选默认取并集，提供“同时属于所选主题”的交集选项。
- 保留自动分类与人工修订记录，支持撤销本次分类修改；用户明确确认的分类才用于后续偏好校准。不得悄悄批量改写已确认归属。

### 4.4 证据问答

1. 选择范围：全部 / 一个或多个主题目录 / 一组文献；多主题默认并集，可选交集，按 source_id 去重；输入问题，保留本次范围快照。
2. 全文检索优先（中文分词或字符 n-gram），可增加向量召回。资料少时不强制引入向量服务。
3. 先展示检索证据。无 Key 时到此为止；有 Key 时只用已检索到且校验通过的原文片段综合。
4. 回答结构：简明回答 → 支持材料 → 不同意见/限制（存在时） → 依据不足项。区分原文引语、模型概括与个人笔记。
5. 每项回答挂接证据卡：文献题名、作者、原文、定位、引用草稿。点击进入原件，突出对应段落或区块。

硬约束：没有证据则说明“当前文献中没有足够依据”；未检索到反对意见只说未找到，不得声称没有反对意见。个人笔记默认不作学术来源，可显式开启后作为“我的判断”单列。删除或改正文献后，关联回答标记为待重新验证。

## 5. 来源记录与《法学引注手册》

目标是支持《法学引注手册》；公开目录资料显示第二版于 2025 年出版。本次未取得可完整核验的第二版条文全文，故**不宣称 DEMO 或现有代码已完全符合第二版体例**。开发时先固定手册版本与用户常用投稿期刊要求，再把已核验规则做成版本化模板和黄金样例测试。

| 类型 | 至少记录的字段 | 缺失处理 |
| --- | --- | --- |
| 期刊文章 | 作者、题名、刊名、年份、期号、起止页、具体引证页；DOI 可选 | 出现缺项清单；不把 PDF 文件页当成印刷页 |
| 专著/章节 | 作者、书名、译者/编者、出版社、出版年、版次、章名、引证页 | 明示待补字段；不同版本不混用 |
| 网页 | 作者/发布机构、标题、网站、发布日期、URL、访问日期、快照 | 无作者/日期保留空值及核验状态，不猜测 |
| 法规/裁判 | 正式名称、发布/裁判主体、文号/案号、日期、条款/段落、权威来源、版本效力信息 | 不自行判断法规效力；把核验任务明确交给用户 |
| 图片/表格/摘录 | 来源文献、图表编号、所在页/工作表及单元格、截图时间 | 缺母文献时标为“来源不完整”，不能输出完整正式引注 |

引注预览与元数据编辑并排。出处记录、全引/简引、重复引注/同上等应分层：MVP 输出独立引注草稿，不模拟 Word 全文上下文，也不自动生成“同上注”。未知内容显示待补标记；草稿可以复制但必须带缺项提示，完成校验后才允许正式模式输出。

本 DEMO 所有作者、文献及页码均为虚构，并在草稿中保留显著提示。绝不将虚构材料伪装为真实法学引文。

## 7. API、费用与安全边界

用户填写兼容服务的 Base URL、模型名与 API Key，连接测试必须可控且标明是否发起收费调用。Key 只在服务端安全存储，前端仅显示配置状态或末四位，不进 localStorage、日志、导出文件或 Git。

默认本地解析；云端调用以“解析/提炼/问答”为独立开关。可以选择始终确认、只对新来源确认或在既定目录/预算内自动调用。模型只获得必要片段或选定图像页，不默认上传全部知识库。记录每次任务费用，提供单篇及每日上限；失败、额度耗尽时回退到已有文本与检索结果。

导入内容视为资料，不视为指令；正文中的提示词不得触发工具执行或更改应用配置。网页抓取限制 http/https，阻止内网/回环地址及重定向绕过；不执行文档宏、嵌入脚本。仅绑定本地接口，原始文件下载按 source_id 授权映射，避免任意路径访问。

## 8. 验收与测试方案

每次改动编写或更新相关测试、运行适用验证，通过后提交对应 Git commit。模型侧以固定可回放响应进行自动测试，真实 API 采用单独可选验收，不能消耗用户真实额度作为默认单元测试。

| 编号 | Given / When | Then |
| --- | --- | --- |
| A01 | 无 Key 导入文本 PDF | 原件可读、正文可检索；明确语义分析尚未执行 |
| A02 | 导入同一文件两次 | 指纹去重；不丢既有笔记；用户看到已存在记录 |
| A03 | 扫描 PDF 或损坏文件 | 显示需 OCR / 失败原因；可回看已保存原件并重试 |
| A04 | 多栏、段内换行、表格混合材料 | 原始内容不变；clean 可恢复；表格有行列及位置，不能误接为正文 |
| A05 | 原件页序与印刷页不同 | 显示两者；引注不冒用文件页序 |
| A06 | 导入 Excel 合并格/公式 | 单元格定位不漂移；公式与缓存值区分；无值不编造 |
| A07 | 摘要缺失、分类冲突或与九类均不相关 | 缺失/冲突进入待整理或待核对；摘要充分且无关联才归“其它”，二者不混同 |
| A08 | 文献仅解析部分章节 | 显示覆盖率及遗漏；不声称全文综述 |
| A09 | 问库中无法回答的问题 | 明确证据不足；不生成无出处的论断 |
| A10 | 点击回答的证据引用 | 打开正确文献与对应区块，定位校验失败时提示不可定位 |
| A11 | 缺作者、年份或引证页 | 给出缺项；不生成貌似完整的正式引注 |
| A12 | API 超时、401、429、超预算 | 不丢原件/笔记；错误可读；不无限重试，不重复计费同一缓存任务 |
| A13 | 重启与导出恢复 | 原件、目录、笔记、引注来源及证据关系一致 |
| A14 | 恶意网页/文档/标题 | 不执行内容指令、不泄露 Key、不访问内网；前端按文本渲染 |
| A15 | 初始化主题目录 | 名称与顺序严格对应 4.3.1 的十类，系统视图不算第十一类 |
| A16 | 标题关键词与摘要中心议题不同 | 以摘要为主，选择最相近主题；依据可查看，不按标题简单误归 |
| A17 | 摘要实质涉及多个主题 | 同时归属相应主题且各有理由；主主题不排斥附加主题 |
| A18 | 多目录展示、并集/交集检索 | 同一 source_id 原件与笔记只存一份；全库与并集结果去重，交集只含同时符合者 |
| A19 | 手动增删主题、修改主主题后重启或重跑分析 | 修改持久化且支持撤销；重新分析不能自动覆盖人工确认结果 |
| A20 | 同类/跨类已确认样本特别相近，但夹有重复样本 | 参考内容而非样本数量；多主题需分别满足实质关联，重复样本不增加权重 |
| A21 | 无 API Key 或模型失败 | 本地有充分依据则归类，否则保留待核对候选；手动分类始终可用 |

分类专项验收集：每类至少 2 份摘要样本（共至少 20 份），另加 4.3.4 的跨主题/背景词样例、缺失摘要、部分解析、重复样本及人工覆盖场景。每份样本由用户或评审者标注期望主题集合、主主题和理由；测试单类最相近、多类漏分/过分、去重和人工调整持久化。以上是后续实现的验收用例，本次 PRD 更新不代表分类代码已经实现。

本次 DEMO 另附 Node 内置测试，覆盖分类、筛选、文本规范化、无依据检索、检索范围、来源提示、URL 安全及存储回退；浏览器手动验收覆盖收录、笔记持久化、证据回跳与小屏布局。DEMO 不依赖现有后端，也不调用现有 `.env` 中的 Key。

## 9. 开发顺序与里程碑

按一个开发者估算 3–4 周，仅作排期参考；先评审再确认实际工作量。

1. **阶段一：收录与阅读闭环（约 1 周）**。核对已有仓库、稳定原件保存、状态、目录、文件预览及笔记；用六类样本跑通 A01–A06。
2. **阶段二：可核对的结构化材料（约 1 周）**。来源编辑、图表区块、全文覆盖、十类摘要分类与多主题人工调整；完成 A15–A21，固定引注手册版本并完成首批黄金引注样例。
3. **阶段三：有证据的问答（约 1 周）**。检索范围、原文回跳、模型路由、费用与证据验证；完成 A07–A12。
4. **阶段四：日用验证（约 1 周缓冲）**。用用户自己的 30–50 份资料试用，修复实际乱码/图表问题，验证导出恢复和 A13–A14。

用户已确认十个一级主题、摘要优先、最相近原则、多主题归属与人工调整。仍可补充的非阻塞信息：覆盖十类及交叉主题的已分类样本、常用引注手册版本/期刊要求、日常文献语言与扫描件占比、每月 API 预算。分类样本用于校准，不再将目录体系列为待确认项。
